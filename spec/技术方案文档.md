## 1. 目标与约束

- 纯静态部署，托管在 GitHub Pages（后续可迁移）
- 本地环境：Node v22.23.1、npm 10.9.8
- 必须满足：SEO 友好、首屏快、写作流程简单（新增 md 即发布）、可随时回滚到现有站点

## 2. 技术选型

| 项 | 选型 | 理由 |
| --- | --- | --- |
| 框架 | Astro（纯静态输出） | 构建时生成真实 HTML，解决 SPA 的 SEO 与分享预览问题 |
| 交互组件 | `@astrojs/vue` + Vue 3 岛屿 | 继续用 Vue 写工具与游戏，无需换技术栈 |
| 内容 | Content Collections（Markdown） | 原生 frontmatter 校验、类型提示、按集合管理 |
| 代码高亮 | Shiki（Astro 内置） | 构建时高亮，零运行时开销 |
| 样式 | 原生 CSS + CSS 变量（Astro 作用域样式） | 设计规则少，无需引入 Tailwind/UnoCSS，减少依赖 |
| 订阅 | `@astrojs/rss` | 官方集成，几行代码 |
| 站点地图 | `@astrojs/sitemap` | 官方集成 |

暂不引入：UI 组件库、状态管理、CSS 框架、TypeScript 严格模式（可后续加）。

## 5. 内容模型

采用 Astro Content Collections，三套集合，frontmatter 由 schema 校验：

**articles**（`src/content/articles/*.md`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | string | 是 | 标题 |
| date | date | 是 | 发布日期，用于排序 |
| summary | string | 是 | 列表与分享摘要 |
| tags | string[] | 否 | 标签 |
| draft | boolean | 否 | 草稿，true 时不参与构建 |

**works**（`src/content/works/*.md`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | string | 是 | 名称 |
| kind | `工具` \| `Demo` \| `软件` | 是 | 类型，用于列表右侧标注 |
| status | `可玩` \| `开发中` \| `计划中` | 否 | 状态 |
| link | string | 否 | 直接使用的外链或站内路径 |
| order | number | 否 | 列表排序 |
| summary | string | 否 | 一句话说明 |

**games**（`src/content/games/*.md`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | string | 是 | 名称 |
| status | `可玩` \| `开发中` \| `计划中` | 是 | 状态 |
| entry | string | 否 | 游戏入口地址，如 `/game.html` |
| summary | string | 否 | 一句话说明 |

## 6. Markdown 渲染

- Content Collections 直接把 Markdown 编译为 AST/HTML，无需运行时解析，也不需要旧方案里的 `import.meta.glob('?raw')`
- 代码高亮由 Shiki 在构建时完成，样式跟随设计令牌（深色底 `#111111`、浅色字 `#F5F2EC`）
- 正文列宽 860px，行高 1.9，与设计文档一致

## 7. Vue 岛屿的使用

只有需要交互的部分才加载 JS：

| 场景 | 指令 | 说明 |
| --- | --- | --- |
| 文章内的小工具、游戏入口 | `client:visible` | 滚动到可见时再加载 |
| 首屏就需要交互的组件 | `client:load` | 立即加载 |
| 依赖 canvas / window 的组件 | `client:only="vue"` | 只在前端渲染 |

静态内容（列表、文章正文）完全不加指令，保持零 JS。

## 8. 样式与设计令牌

把设计文档里的变量落到 `src/styles/tokens.css`：

```css
:root {
  --bg: #ffffff;
  --ink: #111111;
  --ink-2: #555555;
  --ink-3: #999999;
  --line: #e9e9e9;
  --accent: #e45f48;
  --surface-soft: #f1f1f1;
  --font-display: 'Noto Sans SC', system-ui, sans-serif;
  --font-body: 'Noto Sans SC', system-ui, sans-serif;
  --font-mono: 'IBM Plex Mono', ui-monospace, monospace;
  --content-width: 1280px;
  --reading-width: 860px;
}
```

字体通过 Astro 的字体能力或本地字体加载；中文只加载需要的字重（400 / 500 / 700）。

## 9. SEO 与订阅

- 每页输出 `<title>`、`description`、canonical
- Open Graph / Twitter Card 元信息，文章页使用文章标题与摘要
- `@astrojs/sitemap` 生成 sitemap-index.xml
- `@astrojs/rss` 生成 `/rss.xml`
- 站点根地址通过 `site` 配置项统一设置，便于日后换域名

## 10. 部署

- 现阶段：`master` 分支仍是现有 Vue 站点，`web/` 只用于本地开发与预览，不影响线上
- 切换时：修改 `.github/workflows/deploy.yml`，构建目录改为 `web`、输出目录改为 `web/dist`，推送即发布
- 回滚：把 workflow 改回根目录即可，现有站点代码在切换成功前不删除
- 静态生成后每个页面都是独立 HTML 文件，**不再需要旧的 `404.html` 兜底技巧**（那是 SPA 才需要的）

## 11. 迁移方案

| 阶段 | 内容 |
| --- | --- |
| 1 | 在 `web/` 搭 Astro 骨架，实现布局、首页、文章列表与详情 |
| 2 | 迁移现有文章（`src/content/articles/first-post.md` → `web/src/content/articles/`） |
| 3 | 迁移小游戏（`public/game.html` 原样复制到 `web/public/`），作品与游戏集合录入 |
| 4 | 补齐关于页、RSS、sitemap、404 |
| 5 | 本地对比旧站与新站，确认后修改 workflow 切换部署 |
| 6 | 观察一周无问题后，删除根目录的 Vue 站点代码与依赖 |

旧链接兼容：现有文章地址为 `/article/<slug>`，新站为 `/articles/<slug>`。经确认旧文章没有外部引用，**不做兼容处理**，切换后旧地址直接 404；后续如需兼容，可在 `src/pages/article/<旧 slug>.astro` 放一个 meta refresh 跳转页。

## 13. 风险

| 风险 | 应对 |
| --- | --- |
| Astro 大版本升级带来破坏性变更 | 锁版本，按需升级 |
| 中文字体体积大影响首屏 | 按字重加载 + `font-display: swap`，必要时用系统字体兜底 |
| 迁移期间两套代码并存造成混淆 | 明确 `web/` 为新站、根目录为线上，切换后立即清理 |
